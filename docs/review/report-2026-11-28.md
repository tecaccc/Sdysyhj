TASK-011 是一台高效的一致性机器(人类指令 → 全批次 → 核验 PASS → 发版 → 10 Issue 回写,一天内闭环),但**「删除动作」本身不在任何门禁的验收口径内**:批次删除了新 UI 代码(完备——有残留扫描门禁)、也删除了新 UI 测试与若干配置的**消费者**——后者无门禁:ui-xss.test.ts 删除后 NFR-03 断言面归零(能力静默丢失)、tsconfig jsx 与 .gitignore chat.* 的消费者消失后配置滞留(载体静默滞留)、test-cases 基线与现实的形态冲突无注记(跨文档脱钩)。核验如实记录了 coverage delta(t011 §6.1,好),但「如实记录」≠「去向声明」——记录是旁观,声明是义务。**同类的盲区**:任何「删旧留新/删新留旧」批次(还原、退役、收敛)都会产生这三件套丢失;制度化方向 = 删除完备性 + 能力去向双清单(P-09)。第二个类教训:门禁自述与实效不符(R-19「防注释自命中」恰有注释豁口)——门禁本身也需要「防自证」(P-10)。
