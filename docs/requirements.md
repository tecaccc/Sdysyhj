# Sdysyhj 需求文档

> Sdysyhj（山巅一石一壶酒）— Pi Agent for VS Code
>
> 状态：**待评审** ｜ 版本：v0.3 ｜ 更新日期：2026-11-20

---

## 1. 产品定位

Sdysyhj 是一个 VS Code 插件，将 Pi 编程智能体（coding agent）带入编辑器，提供对话式的代码阅读、编写、重构与命令执行能力。

**核心价值：**

- 在编辑器内以自然语言完成编程任务，无需切换到终端 TUI
- 与 pi 共享同一套会话、配置与凭证（`~/.pi/agent/`），终端与插件双端体验一致
- 开箱即用：不强制用户预先安装 pi CLI

**名称释义：** "山巅一石一壶酒"取首字谐音指代 Pi；仓库名 Sdysyhj 承载此意。

## 2. 目标用户与发布范围

| 项 | 决策 |
|---|---|
| 目标用户 | 先内部/个人使用，但按 VS Code Marketplace 可发布标准开发（打包、文档、兼容性测试齐备） |
| 运行时依赖 | 插件内置 `@earendil-works/pi-coding-agent`，免安装；同时优先使用 PATH 中已有的 pi CLI，失败时回退内置运行时 |
| 配置归属 | 完全复用 pi 自有配置（`~/.pi/agent/`：settings、auth、models）；插件 settings 仅存放 UI 相关项，避免两处配置打架 |

## 3. 术语表

| 术语 | 含义 |
|---|---|
| Pi / pi CLI | `@earendil-works/pi-coding-agent` 提供的编程智能体及其命令行程序 |
| RPC 模式 | Pi 的子进程集成模式（`pi --mode rpc`），JSONL 协议通信 |
| 会话（session） | Pi 的一次持续对话，含消息历史、分支、压缩状态，持久化为 JSONL |
| 工具调用（tool call） | Agent 执行 read/bash/edit/write 等工具的动作 |
| steer / follow-up | 运行中插话（steer）/ 排队等本轮结束再发送（follow-up） |
| 内置运行时 | 插件依赖中自带的 pi 运行时（`@earendil-works/pi-coding-agent` 包） |

## 4. 功能需求（MVP）

### 4.1 聊天（P0）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-CHAT-01 | 流式对话 | P0 | 输入 prompt 后实时流式渲染回复（text delta 级别），不阻塞 UI |
| FR-CHAT-02 | Markdown 渲染 | P0 | 回复支持标题、列表、表格、代码块（含语言高亮）、链接、行内代码 |
| FR-CHAT-03 | thinking 折叠 | P0 | 思考过程默认折叠为可展开块，展开后流式显示 |
| FR-CHAT-04 | 工具调用卡片 | P0 | 每个工具调用展示：工具名、关键参数摘要、执行状态（进行中/成功/失败）、可展开查看输入输出；bash 展示命令与输出摘要；大输出截断保留尾部并提供"复制全部" |
| FR-CHAT-05 | 中止运行 | P0 | 运行中可点击 Stop / 命令面板中止（对应 RPC `abort`），UI 恢复可输入态 |
| FR-CHAT-06 | steer 插话 | P1 | 运行中可继续输入，消息以 steer 方式排队注入；提供 steer/follow-up 模式切换 |
| FR-CHAT-07 | 错误展示 | P0 | provider 报错、子进程崩溃、未配置凭证等异常在聊天区展示可读信息与修复指引 |
| FR-CHAT-08 | 状态指示 | P0 | 顶部状态栏显示：当前模型、thinking 等级、运行状态（idle/streaming/aborted）、会话名 |
| FR-CHAT-09 | 流式输出自动跟随 | P1 | 运行状态为 streaming 时（自本轮流式输出开始计）：① 默认跟随——每轮流式开始即默认处于跟随态，跟随期间每次增量渲染后消息区视口保持"在底部"（"在底部"判定 = 视口底缘距滚动底端 ≤40px）；② 打断——用户向上滚动离开底部（距滚动底端 >40px）即停止自动跟随，后续流式增量不得为跟随而强制滚动（增量渲染不推动滚动位置，scrollTop 保持用户所选位置，尊重用户意图）；③ 恢复——用户滚回底部（距滚动底端 ≤40px）即恢复自动跟随，后续增量继续满足①的"在底部"跟随；④ 边界——跟随状态为会话内瞬时 UI 状态：不写入会话文件、不产生消息级标记、不跨插件重启持久化；运行状态为 idle 时不自动滚动（会话载入/切换的一次性初始定位不属本条"自动跟随"范畴） |

### 4.2 会话管理（P0）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-SESS-01 | 新建会话 | P0 | 命令/按钮新建会话，旧会话落盘保留 |
| FR-SESS-02 | 历史列表 | P0 | 列出当前工作区的会话（标题、时间、消息数），点击切换 |
| FR-SESS-03 | 继续会话 | P0 | 切换后完整恢复上下文（含压缩状态），与 pi 端行为一致 |
| FR-SESS-04 | 会话命名 | P1 | 支持手动重命名会话（对应 `set_session_name`） |
| FR-SESS-05 | 分支切换 | P2 | 编辑历史消息产生分支后可切换（依赖 pi 分支树能力，UI 延后到二期可接受） |
| FR-SESS-06 | 单会话工作模式 | P0 | MVP 为单活动会话 + 历史切换；不提供并行多会话标签 |
| FR-SESS-07 | 外部修改提示 | P1 | 当前会话在插件之外被修改（如终端 pi 写入同一会话）时，插件检测到后提示用户刷新，不静默继续使用陈旧状态 |

### 4.3 文件与工作区（P0/P1）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-FILE-01 | 工作区绑定 | P0 | Pi 子进程 cwd = 打开的文件夹；多根工作区取第一个（MVP） |
| FR-FILE-02 | `@file` 引用 | P0 | 输入框中 `@` 触发文件选择器（当前工作区），选中文件路径插入 prompt |
| FR-FILE-03 | 右键发送 | P1 | 资源管理器/编辑器右键"发送到 Pi"，将文件路径或选区作为 prompt 素材 |

### 4.4 模型控制（P1）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-MOD-01 | 切换模型 | P1 | 状态栏/命令面板列出可用模型并切换（对应 `get_available_models` / `set_model`） |
| FR-MOD-02 | 切换 thinking 等级 | P1 | 同上（对应 `set_thinking_level` / `cycle_thinking_level`） |
| FR-MOD-03 | 会话内持久 | P1 | 切换结果随会话保留，重启插件后反映在状态栏 |

### 4.5 命令与集成（P0/P2）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-CMD-01 | 命令面板 | P0 | 至少：Open Chat / New Session / Abort / Show Session History / Report Issue |
| FR-CMD-02 | 输出日志 | P0 | 子进程 stderr、RPC 协议异常写入 Output Channel（Sdysyhj），便于排障 |
| FR-CMD-03 | slash commands / skills | P2 | Webview 输入框支持 `/` 自动补全（透传 `get_commands`）；MVP 阶段命令文本直接发送即可生效 |
| FR-CMD-04 | MCP | P2 | 复用 pi 的 MCP 配置自动生效；UI 无专门管理界面（MVP） |
| FR-CMD-05 | pi 运行时来源 | P0 | 自动模式下：PATH 中存在可用 pi 时优先使用；PATH 无可用 pi 时使用插件内置运行时并能正常对话（开箱即用）；设置中可显式指定 pi 路径，指定后按该路径启动；显式路径无效或启动失败时展示含错误详情的可行动指引 |

## 5. 明确不做（MVP 边界外）

- **Diff & Apply**：Pi 的 edit/write 结果在 VS Code diff 视图确认后应用 —— **二期**（体验关键，但工作量大）
- **图片粘贴/拖拽**（`prompt` 的 images 参数）—— **二期**
- 多会话并行标签页 —— 二期
- 遥测/数据上报 —— 不做（如发布 Marketplace 再评估）
- 独立的凭证/模型配置界面 —— 不做，复用 pi 配置与 `pi auth`
- VS Code Chat API（Copilot 聊天面板）集成 —— 不做（已选自定义 Webview 路线）
- 流式跟随辅助 UI（"回到底部/跳到最新"悬浮按钮、跟随状态指示）与跟随行为设置项（开关/阈值配置）—— 不做（MVP 仅按滚动位置自动判定与恢复，见 FR-CHAT-09）

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 流式渲染不掉帧；面板切换/重开不丢当前运行状态；单次输出 10k+ tokens 时 UI 保持流畅 |
| NFR-02 | 稳定性 | Pi 子进程崩溃自动重启一次并提示；插件宿主异常不得导致 VS Code 不可用（进程隔离） |
| NFR-03 | 安全 | 不在插件日志中明文输出 api-key/凭证；会话数据仅存 pi 原有位置，不另建副本；Webview 渲染内容经消毒，不得执行注入脚本（防 XSS） |
| NFR-04 | 兼容性 | VS Code ≥ 1.85；Windows / macOS / Linux；Node 运行时随 VS Code（不依赖用户安装 Node） |
| NFR-05 | 可观测 | 关键路径（会话创建、prompt、abort、子进程退出）有日志；错误信息含可行动建议 |
| NFR-06 | 可卸载 | 卸载插件不留残留状态（不写工作区 `.vscode` 之外的隐藏文件） |

## 7. 用户体验概要

**布局：** Activity Bar 新增 Sdysyhj 图标 → 侧边栏 Webview 聊天面板（自定义 UI，非 Chat API）。

```
┌──────────────────────────┐
│ Sdysyhj        [⚙][＋][🕘] │  ← 会话操作：设置/新会话/历史
│ ● claude-sonnet-4 · high  │  ← 模型/思维等级/状态，点击可切换
├──────────────────────────┤
│ ▸ User: 帮我重构这个函数    │
│                          │
│   Assistant: 好的，先看一下│  ← Markdown 渲染
│   ▸ 💭 thinking…          │  ← 默认折叠
│   ▸ 🔧 read(src/a.ts) ✔   │  ← 工具卡片，可展开
│   ▸ 🔧 edit(src/a.ts) ✔   │
│   （流式光标 ▍）            │
├──────────────────────────┤
│ [@文件]  输入消息…   [发送] │  ← Enter 发送 / Shift+Enter 换行
│ [■ Stop]  (运行中显示)     │
└──────────────────────────┘
```

**关键交互约定：**

- Enter 发送，Shift+Enter 换行；运行中发送框转为 steer 输入
- 工具卡片默认单行摘要，点击展开输入/输出（输出截断 + "复制全部"）
- 中止后展示"已中止"标记，历史保留
- 无工作区打开时允许聊天，但提示文件工具受限（cwd = 用户主目录）

## 8. 验收标准汇总（MVP 发布门槛）

1. 从零安装插件（无需装 pi CLI）→ 打开面板 → 完成一次"读文件→修改→执行命令"的完整任务
2. 流式输出、工具卡片、thinking 折叠均符合第 7 节约定
3. 会话关闭 VS Code 重开后可从历史恢复，上下文完整
4. 三平台冒烟通过；`pi --mode rpc` 子进程崩溃可恢复并提示
5. 所有 P0 需求验收标准逐条勾选通过

## 12. 验收标准澄清（v0.2.1，总调度裁决）

> 以下 10 项为测试 Agent 上报需求歧义（#1–#10）的逐项裁决，仅澄清验收口径，不变更 FR 范围/优先级；FR 表格本体维持原状。

1. **#1 FR-CMD-03 门禁边界**：MVP 门禁仅含 P0（依 §8-5）；FR-CMD-03 整条为 P2，不计入 MVP 门禁；"命令文本直接发送即可生效"作为 prompt 透传可用性的辅助判定（不阻塞门禁）。
2. **#2 FR-CHAT-04 截断阈值**：默认保留尾部 200 行（对应配置 `sdysyhj.outputTailLines` 默认 200）；超过阈值即截断展示且保留尾部；"复制全部"取完整输出。
3. **#3 NFR-01 量化判据**：采用可判定代理指标——≥10k tokens（≥600 delta）零丢失 + 全量渲染完成 ≤30s + 渲染批处理（增量合并）迹象；FPS/主观流畅不作硬性判定，录屏仅作辅助证据。
4. **#4 FR-CMD-05 "可用 pi"判据**：`pi --version` 退出码 0 且输出含版本号，且版本不低于插件声明的最低支持版本；否则回退内置运行时。
5. **#5 FR-SESS-03 "与 pi 端行为一致"等价判据**：切换会话后重放的历史消息与会话 JSONL 一致（含压缩状态），UI 重建历史完整；除此之外不作独立判定。
6. **#6 FR-CHAT-08 交互归属**：状态栏"点击可切换"的行为归 FR-MOD-01/02 判定；FR-CHAT-08 仅判定四字段展示与状态流转。
7. **#7 FR-SESS-07 检测边界**：会话文件路径/格式属实现细节（由技术基线/核验剧本定义），需求层判定边界 = 外部修改后 ≤5s 内提示刷新且不静默继续使用陈旧状态。
8. **#8 NFR-03 位置边界**："pi 原有位置" = `$HOME/.pi/agent/`（settings/auth/models/会话存储）；插件不得在其他位置落盘会话/状态副本。
9. **#9 §8-1 "从零安装"离线等价口径**：`vsce package` 产出 vsix 本地安装 + PATH 无 pi + 无预置凭证 + mock provider；离线/CI 环境以此为准。
10. **#10 FR-MOD-02 枚举取值**：thinking 等级取值以 pi 侧权威返回为准（需求不固化枚举）；UI 透传展示。
11. **#11 运行状态口径**：运行状态取值为 idle/streaming（error/restarting 为瞬态）；"已中止"是运行结果标记（消息级），不是运行状态；中止（abort）后运行状态必须回到 idle、UI 恢复可输入（与 FR-CHAT-05 及技术设计 §3.2 状态图一致）。
12. **#12 FR-SESS-02"消息数"口径**：= 会话内消息总数（user 消息 + assistant 消息合计）。
13. **#13 FR-SESS-07"不静默继续使用陈旧状态"释义**：检测到外部修改后必须阻止陈旧状态继续被使用——拦截后续交互直至刷新完成，或自动刷新；仅展示提示但继续受理交互 = 不满足验收标准。
14. **#14 `extension_error` 展示通道（FR-CHAT-07 边界）**：pi 运行时扩展系统的 `extension_error` 事件属上游扩展通知——展示通道 = 非阻断通知（toast，一次性），不得进入 FR-CHAT-07 的聊天区错误卡片；完整字段（extensionPath/event/error）必须写入 Output 日志（Sdysyhj 频道，对应 FR-CMD-02 / NFR-05），不得丢弃；同一错误（相同 extensionPath + error）窗口期内去重展示，日志仍全量记录。FR-CHAT-07 本身不变：错误卡片范围 = 需用户行动的错误（provider 报错、子进程崩溃、凭证缺失等）。
